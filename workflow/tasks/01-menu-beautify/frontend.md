# 任务 01 · 菜单页面重新设计 — 前端执行文档

> 任务类型：纯前端视觉重设计。
> 目标：将现有 5 个页面改造成专业、克制、易读的基础设施运维控制台。
> 本文档供其他 AI 执行，执行前必须先阅读 `workflow/workflow.md`、
> `workflow/boundaries/rules.md`、`workflow/docs/07-frontend.md` 和本目录 `boundary.md`。

## 1. 设计目标

现有页面不沿用大面积渐变、紫色主视觉、过度圆角和装饰性卡片风格。
新的设计强调长期使用时的可读性、数据层级和运维状态识别：

- 深石墨色侧栏，冷白色内容区。
- 使用单一蓝色作为品牌色和主要操作色。
- 绿色、橙色、红色只表达状态，不作为装饰色。
- 以表格、筛选栏和清晰分组为主，减少无意义的卡片。
- IP、端口、时间、延迟、ID 等技术数据使用等宽字体。
- 保持现有 Vue 全局构建版、Element Plus、axios、路由和 API 不变。
- 不增加外部 CDN、字体、图片、npm 包或构建链。

## 2. 页面整体布局

```text
┌────────────────────────────────────────────────────────────┐
│ 深色侧栏 │ 顶部路径 / 页面标题                  用户信息     │
│          ├─────────────────────────────────────────────────┤
│ 品牌     │                                                 │
│ 总览     │ 页面内容区                                      │
│ 主机     │ 统计数据 / 筛选条件 / 数据表格                  │
│ 凭据     │                                                 │
│ 审计日志 │                                                 │
│          │                                                 │
│ 系统状态 │                                                 │
└────────────────────────────────────────────────────────────┘
```

- 侧栏宽度约 232px，背景使用深石墨色，不使用渐变。
- 顶栏白底，使用细边框与内容区分隔。
- 内容区使用浅灰背景，页面边距 32px；窄屏降至 20px。
- 页面标题、说明、主要操作按同一行或同一组对齐。
- 主要内容优先占据可视区域，避免大面积空白和装饰元素。

## 3. 设计令牌

在 `template/static/style.css` 的 `:root` 中集中定义并复用以下变量，禁止在页面中重复散落颜色：

```css
--bg-page: #f4f6f8;
--bg-card: #ffffff;
--bg-sidebar: #18212b;
--bg-sidebar-hover: #253342;
--text-main: #1f2933;
--text-sub: #6b7785;
--text-faint: #9aa6b2;
--text-sidebar: #aeb9c6;
--border: #e1e7ed;
--brand: #2563eb;
--brand-soft: #eaf1ff;
--ok: #16a34a;
--ok-soft: #eaf7ef;
--warn: #d97706;
--warn-soft: #fff5e6;
--danger: #dc2626;
--danger-soft: #fceeee;
--neutral: #64748b;
--neutral-soft: #f1f5f9;
```

- 正文使用 `system-ui`、`PingFang SC`、`Microsoft YaHei` 等系统字体。
- 技术数据使用 `Consolas`、`Menlo` 或等宽字体。
- 普通卡片圆角 8px，输入框和按钮 6px，状态标签使用胶囊形。
- 卡片间距至少 20px，表格行高至少 52px。
- 阴影保持轻微，仅用于浮层和弹窗；禁止大范围发光效果。

## 4. 页面设计要求

### 4.1 登录页

采用“品牌说明区 + 登录表单区”的分栏布局：

- 左侧展示 `infra-ops`、平台定位和简短能力说明。
- 右侧展示用户名、密码、登录按钮和错误提示。
- 登录表单保持简洁，不增加无关字段。
- 登录按钮使用品牌蓝色，错误提示使用浅红背景。
- 移动端改为上下排列，表单仍保持居中和足够留白。
- 不使用复杂插画、大面积渐变或外部图片。

### 4.2 总览页

页面重点是快速判断基础设施状态：

- 顶部展示主机总数、在线主机、凭据数量、近期操作等核心指标。
- 统计卡片高度和结构统一，数字清晰但不夸张。
- 下方使用两栏布局：主机状态、最近操作。
- 在线使用绿色，离线使用红色或橙色，未知使用灰色。
- 最近操作使用紧凑列表或时间线，突出时间、动作和目标。
- 数据缺失时展示明确的空状态，不伪造业务数据。

### 4.3 主机页

主机页以数据表格为核心：

- 顶部包含页面标题、状态筛选、搜索入口和“新增主机”主按钮。
- 表格展示状态、名称、地址、系统、延迟和操作。
- 主机名称、IP、端口、延迟使用等宽字体。
- 连接测试必须保留 loading 和防重复提交状态。
- 详情使用抽屉；新增和编辑使用弹窗。
- 操作列保持克制，只有主要操作使用强调色。
- 空状态、加载状态、错误状态保持统一样式。

### 4.4 凭据页

凭据页突出安全边界，而不是突出敏感内容：

- 顶部包含凭据类型筛选、搜索和“新增凭据”主按钮。
- 表格展示名称、类型、用户名、使用主机数、更新时间和操作。
- 密码、私钥、secret 永远不在列表中展示。
- 新增和编辑时明确提示“敏感内容仅写入，不回显”。
- 编辑时留空表示不修改已有 secret。
- 删除操作必须使用确认弹窗，并正确处理后端冲突提示。
- 凭据类型使用低饱和度标签，不使用大面积红色警告。

### 4.5 审计日志页

审计页重点突出时间、动作、目标和来源：

- 顶部包含操作类型筛选和必要的搜索/时间筛选入口。
- 表格展示时间、操作、目标、详情和来源 IP。
- 时间、目标 ID、IP 使用等宽字体。
- 详情单行省略，保留 tooltip 查看完整内容。
- 操作类型按语义使用少量颜色：认证蓝色、主机绿色、凭据橙色或紫色。
- 分页固定在表格底部右侧。
- 空数据只展示简洁提示，不使用夸张插画。

## 5. 组件统一规范

### 5.1 状态标签

统一使用“浅色背景 + 小圆点 + 状态文字”的形式：

- 在线/成功：绿色。
- 告警/负载偏高：橙色。
- 离线/失败：红色。
- 未验证/未知：灰色。
- 执行中：蓝色，可使用轻微呼吸动画。

### 5.2 表格

- 表头使用 12px 辅助文字，不使用厚重底色。
- 行高不低于 52px。
- 行悬停只使用轻微背景变化。
- 单元格垂直居中，操作列统一右对齐。
- 技术字段统一等宽字体。
- 所有页面使用一致的空状态和分页样式。

### 5.3 表单、按钮、弹窗

- 主按钮只保留一个视觉重点，使用品牌蓝。
- 次级操作使用白底细边框按钮或文字按钮。
- 危险操作使用红色，但不使用大面积红色区域。
- 输入框、选择器、按钮高度和圆角保持一致。
- 弹窗标题、内容、底部操作区分层明确。
- 表单标签位于输入框上方，错误提示靠近对应字段。

## 6. 执行顺序

1. 阅读现有页面和 class 结构，确认不改变 API、路由和数据字段。
2. 先建立全局 CSS 变量、字体、颜色、间距和基础组件样式。
3. 实施整体壳层：侧栏、顶栏、内容区和响应式布局。
4. 依次完成登录页、总览页、主机页、凭据页、审计日志页。
5. 最后统一检查表格、筛选、分页、弹窗、抽屉、loading、错误和空状态。
6. 只执行构建验证，不启动服务，不执行自动化测试。
7. 未经用户明确要求，不提交代码、不创建分支、不推送。

每完成一个页面，记录：

- 修改的文件。
- 已完成的视觉组件。
- 未处理的问题。
- 是否超出本任务范围。

## 7. 验收标准

- 5 个页面视觉风格统一，且符合本文档设计方向。
- 页面层级清晰，主要操作有明确视觉重点。
- 表格列对齐，技术字段易读，内容无明显溢出。
- 状态颜色语义统一，登录、loading、错误、空状态可识别。
- 凭据 secret 不显示、不回显、不写入日志。
- 移动端不出现明显横向溢出。
- 不引入外部资源和新依赖。
- 只修改 `boundary.md` 白名单中的前端文件。
- 构建验证使用 `go build ./...`。

## 8. 强制禁止事项

- 禁止启动服务、开发服务器或 Docker。
- 禁止执行自动化测试、端到端测试或浏览器测试。
- 禁止修改后端、API、数据库、vendor 和 workflow 之外的文件。
- 禁止擅自解决与本任务无关的问题。
- 禁止提交、创建分支、推送或重置用户已有改动。

## 9. 交付格式

最终汇报必须包含：

1. 修改文件清单。
2. 每个页面的完成内容。
3. `go build ./...` 的执行结果。
4. 明确说明没有启动服务、没有执行测试、没有提交代码。
5. 遗留问题和需要用户手工确认的内容。
