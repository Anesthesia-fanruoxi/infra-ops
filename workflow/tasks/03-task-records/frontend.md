# 任务 03 · 任务编排重构为「任务记录」— frontend.md（前端执行）

> 菜单名「任务编排」保留；页面内概念全面改「任务记录」。
> 单列表承载全部记录，三态流转：未开始 →（运行）→ 运行中 →（结束）→ 已结束。
> 基线：工作区未提交改动已实现状态 tabs 与历史运行区块移除，在其上继续。

## 1. 文案与语义

1. 卡片标题「编排定义」→「任务记录」；按钮「新建编排」→「新建任务」；
   名称弹窗标题、编辑器标题（编排：xxx → 任务：xxx）、空状态文案、
   各确认弹窗同步改为任务口径。
2. 状态 tabs：全部 / 未开始 / 运行中 / 已结束；state key 改 finished
   （原 completed），排序优先级 running > not_started > finished。

## 2. 列表列

1. 去掉「启用」列（一次性模型下无意义；schema 字段不动，仅不展示）。
2. 新增「结果」列：已结束显示结果徽章（成功/部分成功/失败）+
   `成功 N · 失败 M · 共 K 台`；未开始/运行中显示 -。
3. 名称 / 流水线预览 / 步骤数 / 更新时间列沿用。

## 3. 操作按状态分流

| 状态 | 操作 |
|------|------|
| 未开始 | 运行 / 编辑 / 删除 |
| 运行中 | 进度 / 删除 |
| 已结束 | 详情 / 删除 |

1. 运行：确认弹窗说明「任务记录仅执行一次」，POST /run 后用返回 run_id
   直开详情（现有实现沿用）；结束后刷新列表使状态翻转为已结束。
2. 进度 / 详情：用 row.last_run_id 调 /orchestration/runs/:id 打开矩阵详情；
   running 态自动挂 SSE；行点击 = 查看详情（仅已运行的记录）。
3. 删除确认文案：「将同时删除其运行记录与执行明细」。

## 4. 交互细节

1. 运行确认弹窗文案改任务口径（执行一次，结束后不可重跑）。
2. 详情矩阵、单元格日志展开、SSE 增量渲染全部沿用现有实现，不改。
