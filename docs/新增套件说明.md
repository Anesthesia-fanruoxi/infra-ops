# 新增套件说明（模式 / 角色 / 安装步骤三张解析表）

> 目标读者：要新增一个套件，或要把现有 9 个套件逐个拆出来一一改造的人。
> 核心方法：任何套件都可以先解析出**三张表**——模式表、角色表、步骤表。三张表确定后，
> 后端蓝图 / 角色计划 / 流水线与前端向导 / 运行视图 / 自定义 UI 全部由它们驱动，不写一行引擎代码。
> 契约代码位置：`store/stackkit/`（driver.go / capability.go / plan_helper.go / probe.go）。

---

## 0. 依赖方向铁律（先记住再动手）

```
model ← store/stackkit ← { store/stacks/<key>, store/registry.go } ← api/stack
```

- `store/stacks/<key>` **禁止 import `store`**（与 `store/registry.go` 循环）；套件之间**禁止互相 import**
  （ELFK 复用 ES 的 yml 走资源路径 `stacks/elasticsearch/configs/...`，不走代码依赖）。
- 套件只做**声明与计算**；副作用（写库、SSH、渲染调度）全部留在引擎。
  能力接口一律由引擎**类型断言**调用：未实现即走引擎通用默认，实现了才覆盖。

---

## 1. 第一张表：模式表（他有哪些部署形态）

一个套件 = 蓝图 `model.StackBlueprint`，其中 `Modes []model.StackMode` 是全部部署形态。
**新增套件的第一件事是把模式列全**，每个模式一行：

| 字段 | 语义 | 设计时的问句 |
|---|---|---|
| `Key` / `Label` | 模式键 / 展示名 | 用户在向导第一步看到的选项（redis：主从/哨兵/集群） |
| `Description` | 一句话说明 | 这个形态的拓扑是什么？ |
| `MinHosts` / `HostHint` | 最小主机数 / 提示 | 3 节点 ZK 仲裁？三主三从 6 台偶数？ |
| `AssignMaster` | 是否让用户指定主节点 | 主从类要指定 master；集群类自动选主则不开 |
| `HasBootstrap` | 全员就绪后是否有引导阶段 | CLUSTER CREATE / formatZK 这类「第二阶段」 |
| `DefaultHomeDir` | 默认服务主目录 | 落盘位置约定 |

范例见 `store/stacks/redis/redis.go` 的 `Blueprint()`：三个模式各自的 MinHosts 与
AssignMaster/HasBootstrap 组合就是模式表的落地形态。

**参数也按模式裁剪**：`SharedVars` 是套件级参数（`Modes: []string{...}` 限定只在哪些模式出现，
`Type: "bool"` 前端渲染成开关），`HostVars` 是逐主机参数（端口 / 主目录）。
前端第三步**完全按蓝图变量声明渲染**，不需要套件写表单代码——变量声明清楚，表单自动正确。

## 2. 第二张表：角色表（每个模式里有哪些角色、落在谁身上）

角色 = 角色计划（RolePlan）里的落点单元，也是**前端所有展示的组件粒度**：
向导第二步预览、实例抽屉组件 chip、运行抽屉主机卡片上的组件芯片，读的都是它。
实现 `RolePlanner`（capability.go），用 `Roles` 助手往三组主机上累加角色：

```go
func (d *Driver) PlanRoles(in stackkit.PlanInput) (model.RolePlan, error) {
    plan := in.NewPlan()
    switch in.Mode {
    case "sentinel":
        in.Roles.AddAt("redis", "master", "Redis Master", "", in.Src(), in.Roles.Boot)
        in.Roles.AddRest("redis", "replica", "Redis Replica")
        in.Roles.AddAll("sentinel", "sentinel", "Sentinel")
    default:
        in.FallbackMasterMember() // 未知模式一律走通用兜底（等价拆分前的 default 分支）
    }
    return plan, nil
}
```

解析角色表时逐行回答四个问题：

1. **comp（组件归属）**：这个角色属于哪个组件？comp 是运行视图芯片的聚合键——
   同一主机同一 comp 只出一枚芯片。**独立进程 / 独立端口就给独立 comp**
   （如 redis 哨兵 = `sentinel`，大数据 hive 步骤同时产出 `hive,metastore_db`）。
2. **role / label**：运行期角色键与展示名（master/replica/sentinel/…）。
3. **落点**：`AddAt`（指定主机，通常 `in.Roles.Boot` = 引导机）/ `AddRest`（非引导成员）/
   `AddAll`（全员）；scope 缺省 = 落点角色（缩容保护），`"aux"` = 辅助组件（不保护）。
4. **警告**：拓扑不满、自动落位假设等用 `in.Roles.Warn(...)` 记录，引擎统一收尾。

**契约纪律**（B3 定，全部套件照此办理）：`PlanRoles` 只做「往 `in.Roles` 累加 + Warn」，
返回 `in.NewPlan()`（落点式）；引擎统一做 `PlanHosts` → 驱动警告 → AssignMaster 兜底提示 →
`in.Src()` 来源标注。例外：`SelfPlanning` 清单式套件（目前只有 bigdata）自建 plan.Hosts /
Injected / Masters，引擎检测到 `len(plan.Hosts) > 0` 即不再改写。

## 3. 第三张表：步骤表（安装由哪些步骤组成）

两种形态，按套件复杂度选：

### 3.1 传统两步（简单套件，如 redis）

`Pipeline()` 返回空 → 引擎走 `node（全员装）→ bootstrap（引导机初始化，若该模式 HasBootstrap）`。
`Phase(mode, phase)` 只需给出每个阶段**一枚脚本** + 资源注入表
（`Assets: map[string]string`，占位符 `@@KEY@@` → `stacks/<key>/configs/xxx`）。

### 3.2 有序流水线（组合套件，如 bigdata）

`Pipeline(mode)` 返回 `[]model.StackPhase`，每个阶段一条：

| 字段 | 语义 | 用途 |
|---|---|---|
| `Key` / `Label` | 阶段键 / 展示名 | **运行抽屉顶部步骤条的每一格** |
| `Target` | `all` 全部主机 / `leader` 仅首（主）节点 | leader 阶段归 bootstrap 日志通道 |
| `Component` | 归属组件（逗号分隔） | ① 加装组件按此裁剪 ② 主机卡片芯片状态来源 |
| `FullOnly` | 仅整机部署（create/reinstall）执行 | reset 清理旧环境这类一次性步骤 |
| `Always` | 任何运行都执行 | 收尾校验 / 目录初始化 |

引擎裁剪规则（`api/stack/stack_vars.go selectPipelinePhases`）——设计步骤表时据此排布：

- `create / reinstall`：全量；
- `add_component`：丢 `FullOnly`，保留 `Always` + Component 与新增组件有交集的阶段；
- `scale_out`：丢 `FullOnly` 与 `Target=leader` 的阶段（新节点只跑自己那部分）。

**运行期映射**（这就是「自定义进度展示」的数据源，不需要再写 SSE 代码）：
运行启动时引擎按 `buildRunSteps` 把步骤清单物化进 `stack_run_steps`
（RequiresDocker → 先加「Docker 环境」步；流水线逐阶段；通用套件 = 节点部署 + 集群初始化），
引擎逐步推进 running→success/failed 并经 SSE（`step_key/step_status`）实时推送；
前端步骤条按 seq 渲染，主机卡片组件芯片状态按 `Component` 聚合。
**只要三张表填对，进度展示全自动正确。**

脚本侧注意：每台主机的 node 脚本必须「按 `{{__role}}` / 参数自行认领本机角色」；
脚本间的等待（端口、集群多数派、选主）写在脚本里，失败 `exit 1` 中止——
引擎按主机子阶段状态聚合，不做业务判定。多脚本共用辅助函数时用 `@@HA_SH@@` 式资源注入。

## 4. 落地清单（后端）

按顺序做，顺序即装配：

1. 建 `store/stacks/<key>/`：
   - `<key>.go`：`Driver` 四件套（`Key` / `Blueprint` / `Phase` / `Pipeline`），约 40 行；
   - `plan.go`：`PlanRoles`（第二张表）；
   - 按需 `roles.go` / `vars.go` / `validate.go` / `probe.go` / `defaults.go` / `topo.go` / `endpoint.go`；
   - `scripts/` 与 `configs/`（`go:embed` 唯一声明点在 `store/embed.go`，模式是
     `stacks/*/scripts stacks/*/configs` 递归——套件目录一旦出现 `.go`，脚本必须搬进这两个目录）。
2. `store/registry.go` 的 `stackDrivers` 数组加一行。
   **数组顺序 = 前端套件卡片顺序 = `baseline/blueprint/_order.json`**，动顺序必须同步刷新基线。
3. 新增 `store/stacks/<key>/register.go`（若需装配函数）。

### 4.1 后端可选能力接口（按需实现，不实现走通用默认）

全部在 `store/stackkit/capability.go`，引擎类型断言调用：

| 接口 | 何时实现 |
|---|---|
| `RolePlanner` | **必选**（9 套件全实现） |
| `SelfPlanning` | 清单式角色计划（落点冻结式扩缩容），目前仅 bigdata |
| `CreateValidator` | 创建前有套件专属校验（组件白名单、拓扑约束） |
| `DefaultsProvider` | 运行期参数兜底（cluster_id、replicas 之类） |
| `TopologyBuilder` | 主机数/副本数拓扑校验（redis 集群偶数校验） |
| `VarInjector` | 在通用注入表之上增补或整体替换 per-host 变量 |
| `ScaleGuard` / `ScaleInGuard` | 缩容保护（不许缩掉最后一个仲裁/主节点） |
| `ScaleInDrainer` | 缩容前软下线脚本参数 |
| `ServiceRegistrar` | 服务入口/安装台账登记有专属规则 |
| `RoleNamer` | 运行期角色改名（worker → replica） |
| `BootstrapHostResolver` | 引导机不等于主节点（bigdata NameNode） |
| `InstanceVarInjector` | 实例级参数权威推导（HA 落点矩阵） |
| `ProbePlugin` | 探活（期望容器清单 + 脚本尾片段 + 输出解析 + 汇总提示） |
| `EndpointProvider` | 接入端点生成（缺省给通用 tcp://ip） |
| `AssetProvisioner` | 部署需要离线物料（如 bigdata HA 的 MySQL 驱动 jar）：声明 key/版本/文件名/目标目录/镜像 URL，用户在向导第二步上传或服务端代下，引擎部署前经 SFTP 分发到 `{{home_dir}}` 渲染的目标目录；未就绪不阻塞（脚本内建下载兜底） |

## 5. 落地清单（前端）

前端是**目录化 + 自注册**，通用骨架（`template/static/stacks/common/`）保持零套件分支——
门禁强制校验（套件分支 0、common 无套件专属选择器）。

1. 建 `template/static/stacks/<key>/`：`index.js` + `hooks.js`（按需）+ `style.css` + 组件 js。
2. `index.html` 对应分组里加 `<script>`/`<link>` 两行（**静态引入，顺序 = 套件文件先于挂载壳**；
   组件用文件末尾 `P.register(key, {components:{...}})` 自注册，与引入顺序解耦）。
3. `template/static/stacks/registry.js` 的 `want` 数组加 key（装载冒烟靠它暴露漏引）。

### 5.1 三个自定义挂点（`P.register(key, {...})`）

```js
P.register('redis', {
  forms:  { /* 向导插槽：第二步/第三步差异化 */ },
  hooks:  { /* 通用骨架分发点：返回值/布尔/组件列表 */ },
  components: { /* Vue 局部组件，页面自动汇总注册 */ }
})
```

- **forms（向导差异化）**：`step2Comp`（第二步替换成套件自己的拓扑组件）、`hints`、
  `minHosts(ctx)` / `canStep3(ctx)`（进第三步的门禁）、`visibleSharedVars(ctx, list)`（变量显隐）、
  `extraParams(ctx)`（提交前追加参数）。
- **hooks（通用分发点，按需覆盖）**：向导侧 `step2BlockedHint`、`memberRoleTag`；
  实例抽屉 `instIsHa` / `memTags` / `instTierStyle` / `caDownloadAvailable` / `downloadCa`；
  探活对话框 `verifyTabbed` / `verifyComponents` / `endpointFor` / `verifyCompEndpoints(ByHost)` /
  `verifyCompHostRows` / `verifyCountLabel` / `verifyCompCountLabel` / `verifyHostRole`。
- **样式**：套件专属类名一律 `.stk-<key简写>-*`，写在**自己的 style.css**；
  通用类 `.stk-*` 在 `common/common.css`。common 里出现套件专属选择器会被门禁打回。

> 教训（2026-09-14 实测）：分发方法若被模板**裸引用**（`v-if="fnName"` 不带括号）求值恒真，
> 会造成「按钮在所有套件都出现」。新增分发点必须放 computed，且冒烟里核对。

## 6. 现有套件拆分改造路径（一一改造时照此办理）

对既有套件做「拆出来独立改造」时，**先冻结行为，再动结构，最后放开定制**：

1. **冻结**：确认该套件的行为快照齐备（`baseline/cases/<key>_<mode>*.json` +
   `baseline/render/<key>__<mode>__<phase>.txt` + `_order.json`），缺的先补录；
2. **拆分**：套件目录内「只搬不改、搬完即删」——从引擎/通用文件原样搬迁，改完删旧分支，
   跑快照**逐字节比对**，不许顺手改行为；
3. **改造**：等价基线建立后，再放开 UI/能力定制（改模式表/角色表/步骤表时同步重录快照，
   `_note` 写明差异来源）。
4. 每期收尾跑 §7 全部门禁，做到「不跑 SNAPSHOT_WRITE 即比对通过」。

## 7. 验收门禁（缺一不可）

```
go build ./... && go vet ./... && go test ./store/ ./api/stack/ ./store/repo/
node --check <本次改动的每个 js>
node script/_fe_smoke.js                        # 57 脚本装载 + 模板逐字节比对
python script/check_stack_lines.py --targets    # 行数 + 套件分支 0 + 专属选择器 0
```

基线刷新纪律：`SNAPSHOT_WRITE=1` / `--record` 只允许在**有意变更**时使用，
`metrics.json` 的 `_note` 必须写明每处差异来源；否则按回归处理。
新套件接入时同步新增：快照 case（每模式至少 1 个）、渲染基线（每模式每阶段）、`_order.json`。

## 8. 一页速查（TL;DR）

```
模式表  → Blueprint().Modes            （StackMode 六字段 + SharedVars/HostVars 按模式裁剪）
角色表  → PlanRoles + Roles 助手        （comp 是 UI 组件粒度；独立进程独立 comp；scope 定保护）
步骤表  → Pipeline + StackPhase        （Component 驱动加装裁剪与芯片状态；FullOnly/Always 定时点）
后端    → store/stacks/<key>/ + registry.go   （能力接口按需实现，副作用归引擎）
前端    → stacks/<key>/{index.js,style.css} + index.html + registry.js want
自定义  → P.register(key, {forms, hooks, components})，类名 .stk-<key>-*
门禁    → go test + fe_smoke + check_stack_lines + 快照逐字节
```
